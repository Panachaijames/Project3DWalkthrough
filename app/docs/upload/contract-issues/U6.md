# Contract issues: U6 web screens (upload milestone, 4 Nov 2026)

Written only by step U6 (docs/upload/WORK_BREAKDOWN.md U6). The integration step UI settles each item; "information" items
say how U6 read a loose spot of the design, with nothing to change unless UI decides otherwise.

## U6-1 The plan canvas cannot draw the Floors step's area proposals, level tags or grid labels

U-2 5c: "each source's sheet with the area proposals (dashed) and the level tags and grid labels marked". `PlanCanvasProps`
(frozen by the scaffold, U-15.1) has `area` (one lit area), `flags`, `focus` and no list of boxes or labelled points.
**Workaround (U6's files only):** the proposals are a list of buttons beside the sheet (`a1 (plan, 19 x 28 m)`, then the
"propose again on the wall layers" boxes `w1 ...`); hovering one shows it on the sheet through `area` (lit, the rest
dimmed). A level tag hovered in the list is marked through `focus` (zoom to it) and one info flag (`id 'mark:level'`,
kind `alignment`, title = its label), and picked alignment points the same way (`mark:point:*`). Grid labels are not
marked. **Proposed:** UI or a later step adds `marks?: { at: Vec2; label: string }[]` and `boxes?: Bbox[]` (dashed) to
`PlanCanvasProps`; the Floors step then passes them instead of the flags.

## U6-2 No route makes an office outside createProject

U-8.4: a project with no office gets "an office select (known offices + "New office...")" on the Floors and Save steps,
and the choice is saved into the settings (`office`). `BuildSettings.office` is an office **id**, and the only route that
creates an office is `createProject` (`newOfficeName`). **Workaround:** on the Floors and Save steps "New office..." takes
a name and sets `settings.office` to its slug (`slugify(name, 63)`, the `OfficeMapping.id` pattern), with the note "its
layer roles are remembered when the version is saved". **Needs U5:** `settings_issues()` must accept an office id that
has no `data/mappings/<id>.json` yet, and `saveBuild` with `rememberMapping` must create the file (name = the id). If UI
prefers, the select can offer only the known offices there (one line in `build/OfficeSelect.tsx`: `mode="settings"`
hides "New office..."), or a `createOffice` route can be added.

## U6-3 "Remember for the office" per furniture word has no field

U-8.4 / U-12.3: "Furniture words go to the office only when staff tick 'remember for the office' next to a word."
Neither `FurnitureSettings` nor `SaveBuildRequest` carries such a flag, and `OfficeMapping.furnitureWords` is written by
the API only. **Workaround:** the tick is not offered; a grey family's kind goes into `settings.furniture.words` (the
project's own), as U-12.3 says. **Proposed:** `SaveBuildRequest.rememberWords?: string[]` (families) in a later
milestone.

## U6-4 web.spec.ts checks every card of the list it reads, e2e-* projects included

U6 may change only the 8 count lines and line 65 of `web.spec.ts` / `web-leak.spec.ts` (U-15.3); both now check "the four
seeded projects' cards" and the seeded ids with `e2e-*` filtered out. But `web.spec.ts`'s first test then loops over the
WHOLE list (`for (const p of list)`, not U6's lines) and expects every card's floors, counts, stamp and link: a project
with no version has none of those (its card leads to its draft, U-14.1). **Workaround:** both tests of
`upload.spec.ts` save a version (`e2e-bank` and `e2e-hostile`), so at integration every e2e project has one. If a build
fails there, that loop fails too. **Proposed (UI):** filter the loop the same way as line 65.

## U6-5 The upload-profile script's date argument

ACCEPTANCE A-7: the version's Max script is compared with "the upload-profile script generated at test time with the
build's date". `walkthrough_builder.out.maxscript.maxscript(model_bytes, profile, *, files, units, date)` takes
`date: str` with no format named (U-11.5: `<d Mon yyyy>` in the header). `upload.spec.ts` (real-API branch only,
`apps/web/test/e2e/upload-kit.ts` `uploadProfileScript`) passes `formatDate(result.finishedAt)` (`'4 Nov 2026'`, in the
test computer's time zone), `files` = the build's source names, `units = 'mm'`. **U4 / UI:** confirm the format (or
the time zone the worker uses for "the build's date") and change that one call if it differs.

## U6-6 Keyboard on the Check step: Esc and Delete are the page's

U-12.1 lists "Keyboard: Esc clears, Delete = set aside the selection" with the canvas, but `PlanCanvasProps` has no
callback for a set-aside (the canvas only reports selections). **How U6 did it:** the Check step's container handles
`keydown` (bubbling from the canvas, or anywhere in the step except a field): Escape clears the selection and closes the
opening editor, Delete / Backspace sets the selection aside. **U7:** the canvas should not stop those keys' propagation
(arrows and +/- stay the canvas's).

## U6-7 The units select before the proposal (information)

U-2 5a: "units select per source, enabled once the proposal is in". A source's units block appears once the prepare has
read it (`BuildSourceInfo.units` not null) and its select stays disabled while `settingsRevision` is 0 (the API answers
409 `not_prepared`). The poll keeps running while the first prepare is `done` and the revision is still 0
(`upload/useBuild.ts` `shouldPoll`), so the page sees the adoption without a reload.
