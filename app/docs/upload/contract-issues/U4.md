# Contract issues: U4 (upload milestone)

Written only by step U4 (docs/upload/WORK_BREAKDOWN.md). Each issue: what is wrong or unsaid, what U4 did in its own
files (the workaround), and what the integration step (UI) should settle.

## U4-1 The fitSlabs camera of U-11.2 fails its own check (should be fixed in the design)

U-11.2 gives `away = [0.52 d, 0.53 d, 0.63 d]` (d = the slabs' bounding-box diagonal, at least 20 m) and the check "at
1400 x 880 every slab corner projects inside the canvas, clear of the panel". With the viewer's own maths
(`core/context.ts applyCameraStart`: PerspectiveCamera fov 40, target = slab-box centre at targetY, panned left by half
of min(panel right, width / 2) in metres per pixel; the panel's right edge 372 px from `ui/css.ts`, content-box) the rule
fails on every model tried: corners fall left of the panel or off the canvas (bank v2: x from 238 px, y to 890 px;
suite, house, hotel, mini likewise). The same maths says the hotel page's own camera (away 21.6, 22.05, 26.1) is inside,
so the maths is right and the factors are too small.
**Workaround (out/presentation.py):** the same direction, moved back 5 % at a time (`away x s`, s = 1, 1.05, ...) until
every slab corner is at least 8 px inside the canvas and clear of the panel. Resulting s: bank 1.25, suite 1.1, house
1.3, hotel 1.25, mini 1.4. `camera_view()` is the check (tested at 1400 x 880 for six models, and the viewer constants are
re-read from the viewer's source in a test, so a viewer change breaks the test, not the picture). U7's
`upload-walk.spec.ts` checks the same rule in Edge.
**To settle:** U-11.2's text ("away [0.52 d, 0.53 d, 0.63 d]") or this fitting.

## U4-2 `FixesReport.setAside` has no item keys

`OverlayFloor.setAside` is "items the build set aside (matched fixes)" as keys, but `FixesReport.setAside` entries are
`{fix, matchedBy, items, ambiguous}`: a fix matched by element id or by `sig` removed items whose keys in the new
drawing U4 cannot know. **Workaround:** `overlay.setAside` lists the fix's own `key` for every fix matched with
`items > 0` (exact for key matches, which is every rebuild and same-file re-upload). **To settle:** add
`keys: list[str]` (the removed anchors) to `FixesReport.setAside` entries (U3) and read it here.

## U4-3 The build's date is not in the BuildContext

U-11.5: "The date is the build's date". Neither JobSpec nor BuildContext carries one. **Workaround:** `write_outputs`
takes the moment it runs (UTC, whole seconds): `inputs.json builtAt` is that moment and the script's date (`4 Nov 2026`)
is its date in this machine's time zone. A test that needs the expected bytes of a version's `.ms` (ACCEPTANCE A-7)
generates them with
`node tools/run-builder-py.mjs -m walkthrough_builder.out <model.json> --date "<d Mon yyyy>" --sources dwg:mm,dwg:mm --converter-version 0.14 --out <file.ms>`
and the local date of the run's `finishedAt` (or of the saved version's `source/inputs.json builtAt`); a build that
crosses midnight between its outputs step and `finishedAt` would disagree by a day. **To settle:** whether JobSpec should
carry the date (then `write_outputs` reads it).

## U4-4 MaxTexts profile format (not in upload-contracts.ts)

U-11.5 lists the profile's fields; U4 defines the file (`format: 'max-texts/1'`, checked by `maxscript.check_profile`):
`header` (lines with placeholders; a line `__PLACEDAT__` is replaced by `placedAt`, a line `__NOTES__` by the notes
whose condition holds), `placedAt`, `notes: [{when: always | revitGlass | pictures | furniture | steps, lines}]`,
`tooltip`, `datumSource`, `datumExtra` (whole MAXScript lines after the datum's Levels property), `titleSuffix` (after the
upper-case project name: `__TITLE__`), `builtBy`, `page`, `rolloutSuffix`, `pictures`, and two U-11.5 does not name:
`date` (null: the build's date; the golden profiles pin theirs, 27 Oct and 2 Nov 2026) and `frame` (the hotel's
`__FRAME__` text). The `upload` profile is read at RUN TIME from `fixtures/upload/max-texts/upload.json` (U-11.5 puts
it there), so that file ships with the app, not only with the tests.

## U4-5 The scaffold's fixture maker still writes the max-texts files

`tools/upload/make-fixtures.py` (`part_maxtexts`, U0) writes the provisional outlines over `fixtures/upload/max-texts/*`,
which U4 now owns: `make-fixtures.py --only maxtexts` (or a full run) would undo U4's profiles and break the goldens.
`fixtures/README.md` (not U4's) still lists the provisional sha1s of the three files. **To settle (UI):** drop
`maxtexts` from make-fixtures.py and record the new sha1s in fixtures/README.md: `bank-27oct.json`, `hotel-2nov.json`,
`upload.json` as written by U4 (the tests pin the scripts they make, not the profile files).

## U4-6 Signatures of the out modules (stubs changed)

The scaffold's stubs had `maxscript(model_bytes, profile, *, files, units, date)`, `presentation(model, facts)`,
`stages(replay, model)`. Final: `maxscript(model_bytes, profile, *, date=None, sources=None, converter=None)` (sources =
`[{kind, units}]` in the model's order), `presentation(model)` (the model alone has every fact it quotes),
`stages(replay, model, report=None)` (see U4-7), `overlay(result, ctx)`, `diff(after, before)` and
`build_diff(model, ctx, log)`, `topview_png(model)`. `contracts.write_outputs(result, ctx, log)` is unchanged; it also
accepts `profile=` (default `'upload'`).

## U4-7 ReplayFacts has no per-floor item and layer counts

The bank's replay quotes the items and layers in use per floor (`source.layersInUse` must equal v2's, A-1), which
`ReplayFacts` does not carry. **Workaround:** read from `report.summary.floors[k].items` / `.layers` (the bank summary's
keys, which U3 fills for every floor). When a floor lacks them, the intro's items line and `source.layersInUse` are
left out. `facts.counts` are LINES per category (the noise capped at 6,000 a floor), so the captions quote lines, and
the noise count is not quoted.

## U4-8 Flags without a floor; the units flag

`Flag.id` is `<kind>:<floor>:<12 hex>`, but a `units` flag is about a source (it can serve several floors) and has
`floor: null`. **Workaround:** its id uses `-` for the floor (`units:-:<hex>`, `-` is no floor key character).

## U4-9 Unspecified choices made in U4's files (for the record)

* Legend (U-11.2) for the v1 kinds the bank never had: low, builtin, post with "Walls and lintels"; pane, balustrade
  with "Glass"; deck with "Floor plates"; "Stairs" also when the model has stair lines but no step parts.
* Max kinds outside the bank's 11: each used kind adds exactly one case line and ONE material of its own (`Pane`,
  `Balustrade` with the bank's glass settings; `Low`, `Builtin`, `Deck`, `Post` in the D-5.4 colours), layers `Panes`,
  `Balustrades`, `LowWalls`, `BuiltIns`, `Decks`, `Posts`.
* Max names: a part label, room text, floor name (spinner caption), source name, project or short name that
  `ascii_name` reduces to nothing falls back to: no suffix (`BB_L1_Wall_012`), `room <nnn>`, the floor key,
  `drawing <i>`, the model's photo name (then the prefix). A name that keeps a few ASCII characters keeps them.
* Placeholders are filled in one pass over the template only, never inside drawing names (a room called `__SHA__` stays
  `__SHA__`); the "no placeholder left" check runs on the template before it is filled.
* A part with a loop of fewer than 3 points is refused (`MaxScriptRefused`) where the prototypes crashed in shapely.
  `write_outputs` raises `MaxScriptRefused` (a `ValueError`, message in plain words with the part names) before it
  writes anything; U1 should report it as `build_failed`.
* Diff: parts compared with their holes too (outline AND holes rounded to 1 cm), then a 1.1 cm tolerance pass for values
  on a rounding boundary; `counts[floor]` keys are part kinds, `door` / `window` / `passage`, `furniture`, `rooms`;
  opening fields compared: width, head, sill, subtype, lintel, lintelTop, wallThickness. `against[].ref`: the run id from
  `runs/<runId>/out/model.json`, `v<n>` from `versions/<n>/model.json`.
* Gap report (`tools/upload/gap-report.py`): the walk checks it reads (`--walk`) are a JSON list (or `{probes: [...]}`)
  of `{floor, kind, id, passed, detail}`; U7's `upload-walk.spec.ts` should write that, or UI converts. Known causes
  and classes come from `--classes` (a JSON list of `{floor, metric, cause, class}`); every other difference is listed
  "to classify".
* Output files: `model.json` and `stages.json` compact with no trailing newline (the bank's bytes); overlay, diff,
  openings, pieces and report compact; presentation and inputs indented. All UTF-8, written atomically.
